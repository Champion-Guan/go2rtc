# 实时流传输协议

此模块为 RTSP 协议提供以下功能：

- 流输入：[RTSP client](#rtsp-client)
- 流输出：[RTSP server](#rtsp-server)
 - [Streaming ingest](#streaming-ingest)
 - [Two-way audio](#two-way-audio)

<a id="rtsp-client"></a>

## RTSP 客户端

<a id="configuration"></a>

<a id="configuration"></a>

### 配置

```yaml
streams:
  sonoff_camera: rtsp://rtsp:12345678@192.168.1.123/av_stream/ch0
  dahua_camera:
    - rtsp://admin:password@192.168.1.123/cam/realmonitor?channel=1&subtype=0&unicast=true&proto=Onvif
    - rtsp://admin:password@192.168.1.123/cam/realmonitor?channel=1&subtype=1#backchannel=0
  amcrest_doorbell:
    - rtsp://username:password@192.168.1.123:554/cam/realmonitor?channel=1&subtype=0#backchannel=0
  unifi_camera: rtspx://192.168.1.123:7441/fD6ouM72bWoFijxK
  glichy_camera: ffmpeg:rtsp://username:password@192.168.1.123/live/ch00_1 
```

### 建议

- **Amcrest 门铃**使用者可能需要禁用双向音频，否则活动流可能使呼叫按钮失效。在 YAML 配置的 RTSP 链接末尾添加 `#backchannel=0`
- **大华门铃**可能需要修改 [audio codec](https://github.com/AlexxIT/go2rtc/issues/49#issuecomment-2127107379) 才能正常双向对讲；在同一门铃的其他源添加 `#backchannel=0`，避免重复请求回传通道。双向对讲优先使用 `unicast=true&proto=Onvif`，让门铃接受多种输入音频编码
- **Reolink** 部分型号的 RTSP 实现难以使用，可能应选择其他协议
- **Ubiquiti UniFi** 可能需要关闭 HTTPS 验证，用 `rtspx://` 替换 `rtsps://`，且不要使用 `?enableSrtp` [suffix](https://github.com/AlexxIT/go2rtc/issues/81)
- **TP-Link Tapo** 可省略用户名和密码，因为 go2rtc 支持 [without them](https://drmnsamoliu.github.io/video.html) 登录
- 摄像头有两个 RTSP 链接时，可同时作为源添加，适用于编码不同的情况，例如主码流带 AAC，副码流带 PCMU/PCMA
- 流不稳定时可尝试 [ffmpeg source](../ffmpeg/说明书.md)；不转码时不会增加 CPU 负载
- 流非常不稳定时，可尝试使用 [ffmpeg source](../ffmpeg/说明书.md) 转码

<a id="other-options"></a>

### 其他选项

Format: `rtsp...#{param1}#{param2}#{param3}`

- 自定义超时 `#timeout=30`，单位为秒
- 忽略音频：`#media=video`；忽略视频：`#media=audio`
- 忽略双向音频接口：`#backchannel=0`，对某些不稳定摄像头很重要
- 使用 WebSocket 传输：`#transport=ws...`

<a id="rtsp-over-websocket"></a>

### 通过 WebSocket 传输 RTSP

```yaml
streams:
  # WebSocket 需要认证，RTSP 不需要认证
  axis-rtsp-ws:  rtsp://192.168.1.123:4567/axis-media/media.amp?overview=0&camera=1&resolution=1280x720&videoframeskipmode=empty&Axis-Orig-Sw=true#transport=ws://user:pass@192.168.1.123:4567/rtsp-over-websocket
  # WebSocket 不需要认证，RTSP 需要认证
  dahua-rtsp-ws: rtsp://user:pass@192.168.1.123/cam/realmonitor?channel=1&subtype=1&proto=Private3#transport=ws://192.168.1.123/rtspoverwebsocket
```

<a id="rtsp-server"></a>

## RTSP 服务器

可将任意流作为 RTSP 流获取：`rtsp://192.168.1.123:8554/{stream_name}`

可为外部 RTSP 访问启用密码保护。本机调用（如同机 FFmpeg 或 Home Assistant）始终不校验密码。

### 配置

```yaml
rtsp:
  listen: ":8554"    # RTSP Server TCP port, default - 8554
  username: "admin"  # optional, default - disabled
  password: "pass"   # optional, default - disabled
  default_query: "video&audio"  # optional, default codecs filters 
```

默认仅输出第一个视频轨道和第一个音频轨道，可用 `default_query` 设置修改：

- `default_query: "mp4"`：兼容 MP4 的编码（H264、H265、AAC）
- `default_query: "video=all&audio=all"`：全部源的全部轨道，并非所有播放器都支持
- `default_query: "video=h264,h265"`：仅一个视频轨道（H264 或 H265）
- `default_query: "video&audio=all"`：第一个视频轨道，以及分别输出的全部音频轨道

更多信息见 [codecs filters](../../说明书.md#codecs-filters)。

<a id="streaming-ingest"></a>

## 接收推流

```shell
ffmpeg -re -i BigBuckBunny.mp4 -c copy -rtsp_transport tcp -f rtsp rtsp://localhost:8554/camera1
```

<a id="two-way-audio"></a>

## 双向对讲

购买前很难判断摄像头是否支持通过 RTSP 双向对讲，产品说明通常不提及，需要参考实际用户评价。

通常认为支持 ONVIF Profile T 即支持双向对讲，但实际并不总是如此，ONVIF 支持也不代表 RTSP 实现一定支持。

可通过网页界面 > 流探测检查摄像头是否支持双向对讲。
