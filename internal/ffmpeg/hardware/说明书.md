# 硬件加速

以下情况**不需要**硬件加速：

- 没有使用 [FFmpeg source](../说明书.md)
- FFmpeg 源只使用 `#video=copy`
- FFmpeg 源只对 `#audio=...`（任意音频）转码

使用 `#video=h264`、`#video=h265`、`#video=mjpeg` 视频转码时，**需要**硬件加速。

<a id="important"></a>

## 重要说明

- 硬件加速默认关闭，因为可能不稳定；此默认行为未来可能变化
- 启用后，go2rtc 可自动检测支持的硬件加速
- 仅在支持硬件编码时，go2rtc 才启用硬件解码
- 解码和编码使用同一个 GPU
- 输入编码不受硬件解码器支持时，Intel 和 AMD 会回退到软件解码
- 输入编码不受硬件解码器支持时，NVIDIA 会报错
- 树莓派始终使用软件解码

```yaml
streams:
  # 自动选择硬件编码器
  camera1_hw: ffmpeg:rtsp://rtsp:12345678@192.168.1.123/av_stream/ch0#video=h264#hardware

  # 手动选择硬件编码器（vaapi、cuda、v4l2m2m、dxva2、videotoolbox）
  camera1_vaapi: ffmpeg:rtsp://rtsp:12345678@192.168.1.123/av_stream/ch0#video=h264#hardware=vaapi
```

<a id="docker-and-hass-addon"></a>

## Docker 和 Home Assistant 附加组件

Docker 容器和 Home Assistant 附加组件有两个版本：

- 最新版（Alpine）支持 Intel 核显（带集成显卡的 CPU）和树莓派硬件加速。
- 硬件版（Debian 12）支持 Intel 核显、AMD 和 NVIDIA 显卡。

<a id="intel-igpu"></a>

## Intel 集成显卡

**支持平台：**Windows 二进制、Linux 二进制、Docker、Home Assistant 附加组件。

Intel Sandy Bridge（2011 年）及之后的集成显卡支持 `AVC/H.264` 硬件解码/编码。

Intel Skylake（2015 年）及之后的集成显卡支持 `AVC/H.264`、`HEVC/H.265` 和 `MJPEG` 硬件解码/编码。

更多信息见 [此处](https://en.wikipedia.org/wiki/Intel_Quick_Sync_Video#Hardware_decoding_and_encoding) 和 [此处](https://en.wikipedia.org/wiki/Intel_Graphics_Technology#Capabilities_(GPU_video_acceleration)。

Linux 和 Docker：

- 较新的系统和 Linux 内核可能很重要。例如，作者的 **Debian 10（内核 4.19）**无法工作，升级到 **Debian 11（内核 5.10）**后恢复正常。
- 如遇问题，请检查宿主机是否存在 `/dev/dri/` 目录。

Docker 用户应为容器添加 `--privileged` 选项，以便访问硬件。

**附注：**Linux 使用 [VAAPI](https://trac.ffmpeg.org/wiki/Hardware/VAAPI) 引擎，Windows 使用 [DXVA2+QSV](https://trac.ffmpeg.org/wiki/Hardware/QuickSync) 引擎。

<a id="amd-gpu"></a>

## AMD 显卡

*原作者没有相应硬件进行测试！*

**支持平台：**Linux 二进制、Docker、Home Assistant 附加组件。

Docker 用户应安装 `alexxit/go2rtc:master-hardware`，并添加 `--privileged` 选项以便访问硬件。

Home Assistant 附加组件用户应安装 **go2rtc master hardware** 版本。

**附注：**使用 [VAAPI](https://trac.ffmpeg.org/wiki/Hardware/VAAPI) 引擎。

<a id="nvidia-gpu"></a>

## NVIDIA 显卡

**支持平台：**Windows 二进制、Linux 二进制、Docker。

Docker 用户应安装 `alexxit/go2rtc:master-hardware`。

更多信息见 [此处](https://docs.frigate.video/configuration/hardware_acceleration) 和 [此处](https://jellyfin.org/docs/general/administration/hardware-acceleration/#nvidia-hardware-acceleration-on-docker-linux)。

**附注：**使用 [CUDA](https://trac.ffmpeg.org/wiki/HWAccelIntro#CUDANVENCNVDEC) 引擎。

<a id="raspberry-pi-3"></a>

## 树莓派 3

**支持平台：**Linux 二进制、Docker、Home Assistant 附加组件。

不建议在树莓派 3 上转码。即使使用硬件加速也非常慢，而且转码 2K 以上视频流时可能失败。

## 树莓派 4

## macOS

原作者测试中，M1 CPU 的转码速度比 M1 GPU 更快，优于 Intel 核显，与 NVIDIA RTX 2070 相当。

**附注：**使用 [videotoolbox](https://trac.ffmpeg.org/wiki/HWAccelIntro#VideoToolbox) 引擎。

## Rockchip

- 必须使用来自 [@nyanmisaka](https://github.com/nyanmisaka/ffmpeg-rockchip)、支持瑞芯微的自定义 FFmpeg 构建
  - 静态二进制见 [@MarcA711](https://github.com/MarcA711/Rockchip-FFmpeg-Builds/releases/)
- 需要 Linux 5.10 或 6.1 内核

**Tested**

- [Orange Pi 3B](https://www.armbian.com/orangepi3b/) 搭配 Armbian 6.1，支持 H.264、H.265、MJPEG 转码
