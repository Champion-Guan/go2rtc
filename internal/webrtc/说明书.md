# WebRTC

<a id="webrtc-client"></a>

## WebRTC 客户端

[`v1.3.0 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.3.0)

此源支持四种连接格式。

### Creality

[`v1.9.10 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.9.10)

[Creality](https://www.creality.com/) 3D 打印机摄像头，详情见 [此处](https://github.com/AlexxIT/go2rtc/issues/1600)。

```yaml
streams:
  creality_k2p: webrtc:http://192.168.1.123:8000/call/webrtc_local#format=creality
```

### go2rtc

此格式仅由 go2rtc 支持。与 WHEP 不同，它支持异步 WebRTC 连接和双向对讲。

```yaml
streams:
  webrtc-go2rtc:    webrtc:ws://192.168.1.123:1984/api/ws?src=camera1
```

### Kinesis

[`v1.6.1 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.6.1)

支持使用 WebRTC 协议的 [Amazon Kinesis Video Streams](https://aws.amazon.com/kinesis/video-streams/)。需提供信令 WebSocket 地址，查询参数中包含全部凭据，并在 [JSON format](https://developer.mozilla.org/en-US/docs/Web/API/RTCIceServer) 中指定 `client_id` 和 `ice_servers` 列表。

```yaml
streams:
  webrtc-kinesis:   webrtc:wss://...amazonaws.com/?...#format=kinesis#client_id=...#ice_servers=[{...},{...}]
```

**附注：**对于 `kinesis` 源，可用 [echo](../echo/说明书.md) 调用 `bash`、`python` 或其他脚本语言获取连接参数。

### OpenIPC

[`v1.7.0 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.7.0)

使用开源 [OpenIPC](https://openipc.org/) 固件的摄像头。

```yaml
streams:
  webrtc-openipc:   webrtc:ws://192.168.1.123/webrtc_ws#format=openipc#ice_servers=[{"urls":"stun:stun.kinesisvideo.eu-north-1.amazonaws.com:443"}]
```

### SwitchBot

支持基于 Kinesis Video Streams 的 [SwitchBot](https://us.switch-bot.com/) 摄像头，包括 [Pan/Tilt Cam Plus 2K](https://us.switch-bot.com/pages/switchbot-pan-tilt-cam-plus-2k)、[Pan/Tilt Cam Plus 3K](https://us.switch-bot.com/pages/switchbot-pan-tilt-cam-plus-3k) 和 [Smart Video Doorbell](https://www.switchbot.jp/products/switchbot-smart-video-doorbell)。`Outdoor Spotlight Cam 1080P`、`Outdoor Spotlight Cam 2K`、`Pan/Tilt Cam`、`Pan/Tilt Cam 2K`、`Indoor Cam` 基于涂鸦，不支持此方式。

```yaml
streams:
  webrtc-switchbot: webrtc:wss://...amazonaws.com/?...#format=switchbot#resolution=hd#play_type=0#client_id=...#ice_servers=[{...},{...}]
```

### WHEP

WebRTC 音视频播放器的 [WebRTC/WHEP](https://datatracker.ietf.org/doc/draft-murillo-whep/) 已被 [WebRTC/WISH](https://datatracker.ietf.org/doc/charter-ietf-wish/02/) 标准取代，但部分第三方软件可能仍支持，go2rtc 也支持。

```yaml
streams:
  webrtc-whep:      webrtc:http://192.168.1.123:1984/api/webrtc?src=camera1
```

### Wyze

[`v1.6.1 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.6.1)

这是通过 [docker-wyze-bridge](https://github.com/mrlt8/docker-wyze-bridge) 使用 WebRTC 连接 [Wyze](https://www.wyze.com/) 摄像头的旧方式；无需 docker-wyze-bridge 的原生点对点支持见 [Source: Wyze](../wyze/说明书.md)。

```yaml
streams:
  webrtc-wyze:      webrtc:http://192.168.1.123:5000/signaling/camera1?kvs#format=wyze
```

<a id="webrtc-server"></a>

## WebRTC 服务器

关于 WebRTC，需要了解：

- 浏览器与 go2rtc 之间几乎总是建立**直接的 [peer-to-peer](https://en.wikipedia.org/wiki/Peer-to-peer) 连接**
- Home Assistant、Frigate、Nginx、Nabu Casa、Cloudflare 等软件只参与**建立连接**，不参与**媒体数据传输**
- WebRTC 媒体无法在 HTTP 连接内部传输
- 通常使用客户端和服务器上的随机 UDP 端口建立连接
- 通常通过公共 [STUN](https://en.wikipedia.org/wiki/STUN) 服务器建立局域网外的连接，它们只参与建连，不传输媒体数据
- WebRTC 通常自动发现全部本地和公网地址，并尝试建立连接

使用 STUN 外部连接时：

- 使用 [UDP hole punching](https://en.wikipedia.org/wiki/UDP_hole_punching) 技术穿透 NAT，即使服务器没有直接对公网开放
- 约 20% 的用户可能因 [Symmetric NAT](https://tomchen.github.io/symmetric-nat-test/) 而无法使用此技术
- 公网丢包率较高时，UDP 不适合传输 2K、4K 高码率视频：
  - https://habr.com/ru/companies/flashphoner/articles/480006/
  - https://www.youtube.com/watch?v=FXVg2ckuKfs

<a id="configuration-suggestions"></a>

### 配置建议

- 默认使用 8555 端口的 TCP 和 UDP 建立连接
- 可使用此端口提供外部访问
- 可在 YAML 中修改端口：

```yaml
webrtc:
  listen: ":8555"  # address of your local server and port (TCP/UDP)
```

<a id="static-public-ip"></a>

#### 静态公网 IP

- 在路由器转发 8555 端口，外部端口可以是 8555 或其他端口
- 在 YAML 中添加外部 IP 和外部端口

```yaml
webrtc:
  candidates:
    - 216.58.210.174:8555  # if you have a static public IP address
```

<a id="dynamic-public-ip"></a>

#### 动态公网 IP

- 在路由器转发 8555 端口，外部端口可以是 8555 或其他端口
- 在 YAML 中添加 `stun` 和外部端口
    - go2rtc 会通过 STUN 服务器自动检测外部地址

```yaml
webrtc:
  candidates:
    - stun:8555  # if you have a dynamic public IP address
```

<a id="hard-tech-way-1-own-tcp-tunnel"></a>

#### 进阶方式一：自建 TCP 隧道

有自己的 [VPS](https://en.wikipedia.org/wiki/Virtual_private_server) 时，可建立 TCP 隧道，并按静态公网 IP 方式配置，在 YAML 中使用 VPS 的 IP 地址。

<a id="hard-tech-way-2-using-turn-server"></a>

#### 进阶方式二：使用 TURN 服务器

有自己的 [VPS](https://en.wikipedia.org/wiki/Virtual_private_server) 时，可安装 TURN 服务器，例如 [coturn](https://github.com/coturn/coturn)，配置参考 [example](https://github.com/AlexxIT/WebRTC/wiki/Coturn-Example)。

```yaml
webrtc:
  ice_servers:
    - urls: [stun:stun.l.google.com:19302]
    - urls: [turn:123.123.123.123:3478]
      username: your_user
      credential: your_pass
```

<a id="full-configuration"></a>

### 完整配置

**重要！**请勿直接复制粘贴此示例！

```yaml
webrtc:
  # 为 WebRTC 媒体固定本地 TCP、UDP 端口或两者
  listen: ":8555"            # address of your local server

  # 手动添加额外的主机候选地址
  # 顺序很重要，越靠前优先级越高
  candidates:
    - 216.58.210.174:8555    # if you have static public IP-address
    - stun:8555              # if you have dynamic public IP-address
    - home.duckdns.org:8555  # if you have domain

  # 添加自定义 STUN 和 TURN 服务器
  # 使用 `ice_servers: []` 清除默认服务器并保持为空
  ice_servers:
    - urls: [ stun:stun1.l.google.com:19302 ]
    - urls: [ turn:123.123.123.123:3478 ]
      username: your_user
      credential: your_pass

  # 自动发现逻辑的可选过滤列表
  # 某些设置仅在未指定固定 UDP 端口时有效
  filters:
    # 自动发现后发送的主机候选地址列表
    # 包括 listen 选项中的候选地址
    # 使用 `candidates: []` 移除全部自动发现候选地址
    candidates: [ 192.168.1.123 ]

    # 启用本地主机候选地址
    loopback: true

    # 连接使用的网络类型列表
    # 包括 listen 选项中的候选地址
    networks: [ udp4, udp6, tcp4, tcp6 ]

    # 连接使用的网络接口列表
    # 包括未指定主机的 listen 选项（空主机）中的网络接口
    interfaces: [ eno1 ]

    # 连接使用的主机 IP 地址列表
    # 包括未指定主机的 listen 选项（空主机）中的 IP 地址
    ips: [ 192.168.1.123 ]

    # 连接使用的随机 UDP 端口范围 [最小值, 最大值]
    # 与 listen 选项无关
    udp_ports: [ 50000, 50100 ]
```

默认情况下，每个直接 WebRTC 连接使用**固定 TCP 和 UDP 端口**：`listen: ":8555"`。

也可对全部连接使用**固定 TCP、随机 UDP 端口**：`listen: ":8555/tcp"`。

还可关闭 TCP，仅使用随机 UDP 端口：`listen: ""`。

<a id="configuration-filters"></a>

### 配置过滤器

**重要！**默认排除全部类似 Docker 的候选地址（`172.16.0.0/12`），无法禁用此行为。

过滤器可排除不需要的候选地址。额外地址本身不改善或恶化连接，但错误过滤可能使连接失效。不清楚其含义时，请跳过此设置。

例如 go2rtc 安装在宿主机且存在无用接口，可通过 `interfaces` 或 `ips` 仅保留相关接口。服务器支持 IPv6 但家庭网络不支持时，也可排除 IPv6 候选地址。

```yaml
webrtc:
  listen: ":8555/tcp"         # use fixed TCP port and random UDP ports
  filters:
    ips: [ 192.168.1.2 ]      # IP-address of your server
    networks: [ udp4, tcp4 ]  # skip IPv6, if it's not supported for you
```

例如 go2rtc 运行在隔离的 Docker 容器（[Frigate](https://frigate.video/)）中，不应过滤 Docker 接口，否则将无法建立连接；但可过滤其他设备无法访问的 Docker 候选地址。

```yaml
webrtc:
  listen: ":8555"                   # use fixed TCP and UDP ports
  candidates: [ 192.168.1.2:8555 ]  # add manual host candidate (use docker port forwarding)
```

## 接收推流

### 接收推流：浏览器

[`v1.3.0 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.3.0)

可将任意电脑或手机浏览器变成支持视频和双向音频的网络摄像头，也可广播电脑屏幕：

1. 在 `go2rtc.yaml` 中创建空流
2. 打开 go2rtc 网页界面
3. 打开对应流的 `links` 页面
4. 选择 `camera+microphone` 或 `display+speaker`
5. 打开 `webrtc` 本地页面（go2rtc **必须使用 HTTPS**），或通过 [WebTorrent](../webtorrent/说明书.md) 技术打开 `share link`（默认使用 HTTPS）

### 接收推流：WHIP

[`v1.3.0 新增`](https://github.com/AlexxIT/go2rtc/releases/tag/v1.3.0)

可使用 **OBS Studio** 或其他支持 [WHIP](https://www.ietf.org/archive/id/draft-ietf-wish-whip-01.html) 的直播软件。此标准在原文写作时尚未获批，可下载 OBS Studio [dev version](https://github.com/obsproject/obs-studio/actions/runs/3969201209)：

- 设置 > 推流 > 服务：WHIP > `http://192.168.1.123:1984/api/webrtc?dst=camera1`
